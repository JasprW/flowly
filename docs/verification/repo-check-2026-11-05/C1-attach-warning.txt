对话渲染有问题
Flowly's session pane renders every ui/app fenced block as a plain code dump, because plugin timeline transformers only run in the host session view. Detect ui/app fences in parseSessionMarkdown/SessionMarkdown and render a compact collapsed notice instead (for example: Inline UI — open in Paseo to view it live), keeping the source copyable. Done when: an agent reply containing a ui block shows the notice in the card session preview on desktop and phone, catalogs cover the new string, and client tests cover the fence detection.
Why: This research card was filed because ui blocks looked unrendered; the flowly preview surface will keep creating that impression for every Card-wrapped reply even when everything works.
Context:
Files: client/session-transcript.tsx (TranscriptEntry renders SessionMarkdown for agent replies, ~line 461), client/session-content.tsx (SessionMarkdown code-block branch, ~line 165), client/session-markdown.ts (parseSessionMarkdown). Constraint: plugin timeline transformers (genui's addTimelineTransformer in its index.client.tsx) run only in the host session view, never inside flowly's own preview, so live rendering there is not possible. AGENTS.md UI rules apply (plain UI, all new strings in every catalog under shared/i18n/, npm test enforces).
